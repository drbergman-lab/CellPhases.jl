2026-10-15 — A separate package from SpaceTimeCorrelations, no shared base

Decided: CellPhases is its own package, with no common base package. Why: SpaceTimeCorrelations computes the pooled correlation from per-frame values and needs no IDs and no oscillation. CellPhases needs tracked agents with long tracks and one dominant rhythm, and pulls in DSP.jl. The two share input conventions only (per-frame positions, values, IDs; PhysiCell snapshots). Analyses that use both, such as checking that the pooled correlation peak does not drift, belong in analysis scripts.

2026-10-15 — One time unit, the user's; fs always passed; band required

Decided: the band is given as periods (pmin, pmax), together with trim, minlength and the frame interval dt, all in one time unit the user chooses; no unit is named or assumed. Frames appear only in frames selections and in results. bandpassFilter converts to cycles per time unit and always passes fs = 1/dt. band has no default (it is a time scale of the system studied); order = 3 does. The filter test measures the realised response at pmin, pmax and mid-band for four frame intervals. Why: the prototype once built the filter without fs; DSP read the cutoffs as fractions of Nyquist and passed periods of about 200–600 minutes instead of 100–300. The spurious "upward wave" it produced survived every pure-sine check. The mistake was mixing units (normalised frequency against periods), not the choice of unit; requiring everything in the unit of dt leaves nothing to mistranslate.

2026-10-15 — No transform by default

Decided: transform = identity by default; log is opt-in. Why: the prototype logged notch because notch is heavy-tailed, a property of that signal, not of the method. A log default would also make cellPhases fail on any value ≤ 0. Like the band, it is the user's modelling choice.

2026-10-15 — Masking off by default

Decided: low-amplitude masking is opt-in (mask = q, per-track amplitude quantile). Why: it removes ill-defined phases but biases what remains toward strongly oscillating moments; that trade-off is the user's to make. Phase-defect (spiral core) counting was also considered and left out of the first version.

2026-10-15 — trim and minlength derived from the band

Decided: trim defaults to the filter's memory and minlength to 2trim + 2·band[2], both in the unit of dt. Why: the prototype fixed 18 and 90 frames for 10-minute frames and a 100–300-minute band. Both are really properties of the filter: 18 frames was "about the filter's memory", and 90 frames "five cycles plus trim". Deriving them keeps them right when the band or the frame interval changes. For the prototype's settings the derived values are 18 frames, as before, and 96 frames rather than 90.

2026-10-15 — PhysiCell input through cellDataSequence

Decided: the extension reads through PhysiCellOutput's cellDataSequence with include_cell_type_name = true and filters cell types itself. Why: cellDataSequence already groups each cell's values by ID across snapshots and drops dead cells; a second reader would duplicate it.

2026-10-15 — Makie recipes in an extension, not MakieCore

Decided: Makie recipes live in a package extension on Makie; RecipesBase recipes stay in core. Why: the plan was MakieCore recipes in core, but Makie 0.24 folded MakieCore into Makie and no longer depends on it (the last MakieCore, 0.10, pairs with Makie 0.23). Recipes written against MakieCore would be invisible to current Makie. An extension also gets the full Makie API, including preferred_axis_attributes for the rose's equal-aspect, undecorated axis.

From man/plotting.md

2026-10-15 — Plot data in core, recipes from it, no packaged composite

Decided: the core has plot-data functions and RecipesBase recipes built on them; no multi-panel figure is packaged. Why: plot data is plain numbers, so it carries no plotting dependency and serves any package. A composite figure is an analysis choice (which signals, which panels, which cross- check with SpaceTimeCorrelations) and stays in analysis scripts.

From man/plotting.md

2026-10-15 — Time-shift surrogates as the null

Decided: the null for coherence and the order parameter is the time-shift surrogate, drawn per track. Rejected: the prototype's per-frame shuffle of phases among agents. Its mean is a fine baseline to subtract, but its shuffles are independent from frame to frame while the real phases are correlated across frames, so its band is far too narrow for p-values.

From man/synchrony.md

2026-10-15 — Speeds relative to the agents

Decided: ω is each agent's own phase advance, so speeds are relative to the agents. Why: the question is how a signal travels through the tissue, not how far the tissue itself moves. The prototype also computed a speed with one global period for all cells; per-agent ω is the honest version and is the one kept.
